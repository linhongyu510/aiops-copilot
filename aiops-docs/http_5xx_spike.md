# HTTP 5xx 错误率突增处理方案

## 识别信号

服务端 5xx 比例、请求量和延迟发生变化。必须按状态码、路由、实例、版本和下游依赖拆分。

## 排查顺序

1. 确认影响范围和错误预算消耗速度。
2. 按 500/502/503/504 区分应用异常、网关后端、不可用和超时。
3. 对齐发布、配置、流量和依赖告警。
4. 抽取同 request ID 的入口日志、异常栈和下游调用。
5. 比较健康与异常实例。

## 止损与恢复

回滚可疑版本、摘除异常实例、限流或启用降级。避免同时修改多个参数破坏归因。恢复后验证错误率、延迟和关键业务成功率。

## 升级条件

错误预算快速耗尽、核心交易失败或根因跨多个依赖时启动正式事故响应。
