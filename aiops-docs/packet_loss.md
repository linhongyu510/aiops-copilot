# 网络丢包与抖动处理方案

## 识别信号

请求超时、重传、RTT 波动和吞吐下降同时出现。ICMP 丢包不一定代表业务 TCP 丢包，需要结合真实协议。

## 排查顺序

1. 明确源、目标、协议、端口和故障时间窗。
2. 比较客户端、服务端与中间负载均衡的重传和错误。
3. 检查网卡 drop/error、队列、带宽利用率和 MTU。
4. 分段测试节点内、同网段、跨区链路。
5. 对齐网络策略、路由和扩容变更。

## 止损与恢复

切换健康链路、降低非关键流量或启用合理重试预算。禁止无上限重试放大拥塞。恢复后验证业务 P95、重传率和错误率同步回落。

## 升级条件

多服务跨区同时异常、物理链路错误或路由收敛问题时升级网络团队。
