# 文件描述符耗尽处理方案

## 识别信号

应用出现 Too many open files，连接建立失败，进程 fd 数接近软/硬限制。

## 排查顺序

1. 查看系统级和进程级 fd 使用与限制。
2. 按 socket、普通文件、pipe 等类型分类。
3. 检查连接状态分布、日志文件和未关闭句柄。
4. 对齐流量、连接池、超时及版本变更。
5. 判断是合理容量不足还是泄漏。

## 止损与恢复

限流新连接或重启泄漏实例只能作为临时止损。提高 limit 前必须确认内存和内核容量；根治应关闭泄漏句柄、复用连接并设置超时。

## 升级条件

系统级 file-nr 接近上限、多个进程同时异常或泄漏无法定位时升级系统与应用团队。
