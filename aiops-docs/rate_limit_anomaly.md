# 限流异常处理方案

## 识别信号

429 或业务限流码突增。需区分真实流量超额、阈值配置错误、分布式计数异常和重试风暴。

## 排查顺序

1. 按租户、接口、实例和限流规则拆分拒绝量。
2. 比较进入流量、允许量、拒绝量和后端容量。
3. 检查规则版本、时间窗口、令牌补充和时钟偏差。
4. 分布式限流检查 Redis/协调服务连通性与一致性。
5. 检查客户端是否尊重 Retry-After。

## 止损与恢复

优先抑制异常调用方并启用退避；调整阈值必须基于容量和错误预算。不要直接关闭核心保护。恢复后观察后端饱和度没有因放量恶化。

## 升级条件

关键客户被误伤、计数全局漂移或限流关闭会触发级联故障时升级网关与业务负责人。
