# Redis Slowlog 与延迟尖峰处理方案

## 识别信号

客户端 P99 延迟升高，Slowlog 出现高耗时命令，instantaneous_ops_per_sec 或 blocked_clients 异常。

## 排查顺序

1. 读取 Slowlog 的命令名、耗时和发生时间，参数保持脱敏。
2. 检查大 Key、全量集合操作、Lua 脚本和 KEYS 类命令。
3. 对齐 RDB/AOF、fork、主从同步与系统 IO。
4. 检查客户端连接池、网络 RTT 和超时重试风暴。
5. 集群模式确认热点槽位。

## 止损与恢复

限流异常调用方，把大操作改为分页或渐进处理；不要在生产执行未经约束的全库扫描。恢复后验证 Slowlog 新增速率和端到端 P99。

## 升级条件

主线程持续阻塞、持久化反复失败或热点无法通过业务拆分缓解时升级缓存与应用团队。
