# 应用线程池耗尽处理方案

## 识别信号

活跃线程达到上限、队列持续增长、拒绝次数增加，接口延迟上升但 CPU 未必饱和。

## 排查顺序

1. 查看 active、pool size、queue size、reject count 和任务耗时。
2. 获取线程栈，区分锁等待、网络 IO、数据库和 CPU 计算。
3. 检查下游超时、连接池与重试是否导致线程长期占用。
4. 对齐流量和发布变更。
5. 判断队列是吸收短峰还是掩盖持续过载。

## 止损与恢复

限流、快速失败或降级慢下游；盲目增大线程和队列可能放大内存与下游压力。恢复后验证队列清空且拒绝率归零。

## 升级条件

线程死锁、核心下游长期不可用或多个实例同时耗尽时升级应用负责人。
