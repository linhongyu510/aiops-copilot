# MySQL 锁等待与死锁处理方案

## 识别信号

事务延迟升高、连接堆积，出现 lock wait timeout 或 deadlock。死锁会自动选择牺牲事务，长锁等待则可能持续放大。

## 排查顺序

1. 读取当前事务、等待关系和锁对象。
2. 定位持锁事务的开始时间、SQL、来源服务和是否处于 idle。
3. 检查事务是否访问过多行、顺序不一致或缺少索引。
4. 对齐批任务、DDL 和发布变更。
5. 判断被阻塞链是否影响核心请求。

## 止损与恢复

终止事务属于变更操作，必须审批并先确认可回滚性。应用侧可临时降低并发、缩短非核心事务或暂停批任务。修复后统一锁顺序并缩短事务边界。

## 升级条件

阻塞主链路、持锁事务来源不明或涉及资金等强一致业务时立即升级 DBA 与业务负责人。
