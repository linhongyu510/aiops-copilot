# Kafka Consumer Lag 处理方案

## 识别信号

Consumer Group lag 持续增长，消息端到端延迟超过目标。先判断生产突增、消费变慢还是分区不可用。

## 排查顺序

1. 按 topic/partition 查看 current offset、log end offset 和 lag 斜率。
2. 检查消费者实例数、活跃成员、消费速率和错误率。
3. 对齐下游数据库、外部 API、GC 和线程池耗尽。
4. 检查分区数是否限制最大并行度，是否存在热点分区。
5. 查看 rebalance、超时和重复消费日志。

## 快速缓解与恢复

暂停非关键生产者、扩容消费者或降级耗时下游；扩容不得超过有效分区并行度。恢复标准是消费速率高于生产速率且 lag 持续收敛。

## 升级条件

核心事件接近保留期、存在数据丢失风险或 Broker 异常时升级消息平台负责人。
