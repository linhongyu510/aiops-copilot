# MySQL 慢查询处理方案

## 识别信号

接口延迟与数据库查询时间同步升高，slow log 或 performance_schema 中出现执行时间、扫描行数异常的语句。

## 排查顺序

1. 按总耗时、平均耗时和调用次数分别排序，避免只看单次最慢。
2. 使用 EXPLAIN 检查访问类型、索引、扫描行数、临时表和 filesort。
3. 核对统计信息、数据分布和参数选择性。
4. 检查锁等待、磁盘 IO、Buffer Pool 命中率与连接池排队。
5. 对比发布前后的 SQL 模板和执行计划。

## 止损与恢复

优先限流高成本入口、关闭非关键批任务或切换缓存。索引变更应在影子环境验证写放大和磁盘空间，禁止在高峰直接执行未经评估的 DDL。

## 升级条件

执行计划突然全局漂移、主库 IO 饱和或需在线 DDL 时升级 DBA。
