# MySQL 主从复制延迟处理方案

## 识别信号

Replica 延迟持续增长，读写结果不一致，relay log 积压或复制线程异常。单一 Seconds_Behind_Source 不能覆盖所有延迟形态。

## 排查顺序

1. 检查 IO/SQL 线程状态、最后错误和 GTID 位点差。
2. 对齐主库写入峰值、大事务、DDL 和从库资源使用。
3. 检查从库磁盘 IO、并行复制配置与锁等待。
4. 判断延迟读是否已影响业务一致性。
5. 检查网络带宽和跨地域抖动。

## 止损与恢复

强一致请求临时回主库或关闭延迟副本读流量；暂停非关键大事务。不要在未确认位点时重建复制。恢复后观察位点差持续收敛。

## 升级条件

复制线程停止、GTID 不一致、延迟持续发散或需要故障切换时升级 DBA。
