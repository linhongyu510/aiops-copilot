# Linux inode 耗尽处理方案

## 识别信号

磁盘仍有容量但创建文件失败，出现 No space left on device，inode 使用率接近 100%。

## 排查顺序

1. 分文件系统检查 inode 使用率。
2. 逐级统计目录文件数量，定位小文件集中区域。
3. 检查日志切分、临时文件、缓存、消息落盘和容器层。
4. 核对清理任务是否失败及保留策略是否变化。
5. 评估删除对进程和审计要求的影响。

## 止损与恢复

先停止异常文件生成源，再按保留策略清理确认可删除的临时文件。禁止使用跨根目录的无边界删除命令。恢复后验证 inode 增长速率回归正常。

## 升级条件

文件属于业务数据、目录扫描影响在线服务或需重建文件系统时升级存储与业务负责人。
