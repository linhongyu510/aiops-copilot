# RabbitMQ 队列积压处理方案

## 识别信号

messages_ready 持续增长、messages_unacknowledged 长时间不下降，消费者利用率或 ack 速率异常。

## 排查顺序

1. 比较 publish、deliver、ack 速率及积压斜率。
2. 检查消费者连接、channel、prefetch 和处理错误。
3. 区分 ready 高与 unacked 高：前者通常消费不足，后者可能处理慢或未确认。
4. 检查节点磁盘/内存告警、流控与网络分区。
5. 核对死信、重试队列是否形成循环。

## 止损与恢复

限制异常生产者，扩容健康消费者，必要时降级耗时下游。清空队列是不可逆变更，禁止作为默认处理。恢复后确认积压持续收敛且无重试风暴。

## 升级条件

消息接近 TTL、磁盘告警阻断发布或涉及不可重复业务时升级消息平台和业务负责人。
